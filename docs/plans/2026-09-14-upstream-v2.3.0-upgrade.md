**Why:** security. Upstream v2.1–2.3 patch 13+ dependency advisories, including
Next.js middleware/proxy-bypass and SSRF-in-Server-Actions. Mission Control's
authentication runs in middleware and the console is public at
`virtualcarhub.cloud`, so these apply directly. Also: global API key hashed at rest,
gateway bearer token no longer exposed to viewer accounts, 52 production
vulnerabilities cleared.

**Is it safe:** yes, with the steps below.

Work in a throwaway worktree off `main` (detached, no branch, removed afterwards).

```bash
cd /root/openclaw-mission-control
git fetch origin --tags
```

Use a real merge commit. **Never** squash and **never** `-s ours`: a true merge

## 5. Phase 2 — Staging rehearsal on this box (no production impact)

Run the merged build against a **copy** of production data on a private port.

```bash
S=/root/mc-staging
install -d -m 700 "$S/data"
node -e "new (require('better-sqlite3'))('/var/lib/mission-control/mission-control.db',{readonly:true}).backup('$S/data/mission-control.db')"
cp -a /var/lib/mission-control/.generated-secrets "$S/data/"

set -a && . /etc/mission-control/mission-control.env && set +a
PORT=3006 HOSTNAME=127.0.0.1 MISSION_CONTROL_DATA_DIR="$S/data" \
MISSION_CONTROL_TEST_MODE=1 MC_COOKIE_SECURE=false \
```

and `public` into the standalone folder, without which the UI loads with no CSS or JS.

and the security auto-fix endpoint. Do not use mutating screens (gateway config,
runtime setup, pairing) in staging: they act on the real OpenClaw state directory.

## 6. Phase 3 — Cutover

Deploy the exact artifact that passed staging; do not rebuild in the live directory
(a build there changes static files under the running server).

```bash
# 1. Safety copies
TS=$(date +%Y%m%d-%H%M%S)
node -e "new (require('better-sqlite3'))('/var/lib/mission-control/mission-control.db',{readonly:true}).backup('/var/lib/mission-control/mission-control.db.pre-upgrade-$TS')"
rm -rf /root/.next-rollback && cp -a /root/openclaw-mission-control/.next /root/.next-rollback
git -C /root/openclaw-mission-control rev-parse HEAD > /root/.pre-upgrade-commit

# 2. Move main to the merge commit (source + new start scripts)
cd /root/openclaw-mission-control
git merge --ff-only "$(git -C /root/mc-upgrade-wt rev-parse HEAD)"

# 3. Swap in the tested build (~30 s down). Stop first so no files change under a running server.
systemctl stop mission-control.service
rsync -a --delete /root/mc-upgrade-wt/.next/ /root/openclaw-mission-control/.next/
systemctl start mission-control.service

# 4. Refresh dev tooling in the live checkout (does not affect the running build)
pnpm install --frozen-lockfile
```

Do **not** push to GitHub yet.

## 7. Rollback

**Trigger:** any post-cutover check fails and is not fixable in 15 minutes, or login/gateway is down.

**Code-only rollback** (keeps post-cutover data; valid because the rehearsal passed):

```bash
systemctl stop mission-control.service
rsync -a --delete /root/.next-rollback/ /root/openclaw-mission-control/.next/
git -C /root/openclaw-mission-control reset --hard "$(cat /root/.pre-upgrade-commit)"
systemctl start mission-control.service
( cd /root/openclaw-mission-control && pnpm install --frozen-lockfile )   # tooling back in step
```

**Full rollback** (if problems persist): also stop the service and restore
`mission-control.db.pre-upgrade-$TS` over the live DB, removing `-wal`/`-shm` first.
This discards writes made after cutover.

Local `main` can be reset freely because nothing was pushed.

### Phase 2 findings (both fixed in `70a3cac`)

1. **`ws` bundling broke every gateway RPC.** In the standalone build, webpack bundled
   `ws` and its optional `bufferutil` shim, so every outbound frame ≥ 48 bytes threw
   `TypeError: b.mask is not a function` (uncaughtException) and `node.list` timed out →
   empty Nodes panel; chat forward, sessions and spawn would have failed the same way.
   Fix: `serverExternalPackages: ['ws']` — ws is now traced into
   `.next/standalone/node_modules/ws`. Verified: nodes list both spokes, sessions load,
   0 errors in the log.
2. **Noisy warning per agent per `/api/agents` call**: upstream's `readWorkspaceFile`
   warned on a missing optional `identity.md`. ENOENT is now silent.

Side effect to know about: on start, Mission Control registers its own origin in
`gateway.controlUi.allowedOrigins` of the real `openclaw.json`. Staging added
`http://127.0.0.1:3006`; removed afterwards (backup `/root/openclaw.json.bak-prestagingclean-*`).
The running gateway never applied it (that key needs a gateway restart, which was not done).
